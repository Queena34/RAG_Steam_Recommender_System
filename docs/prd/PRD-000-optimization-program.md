## 1. 本文档的定位

**`OPTIMIZED_DESIGN.md` 是范围与技术依据的唯一来源。** 它记录了完整的问题诊断、方案论证和取舍理由。

**本文档是执行台账**：把设计文档里的方案拆成可独立交付、可独立验收的变更项，跟踪各自状态，并链接到对应的子 PRD。

**两者的分工：**

| | `OPTIMIZED_DESIGN.md` | PRD-000 | 子 PRD |
|---|---|---|---|
| 回答 | 为什么这么做、原理是什么 | 做哪些、做到什么程度、现在到哪了 | 这一项具体怎么做、怎么验收 |
| 变更频率 | 低，方案有实质变化才改 | 每完成一项就更新状态 | 一事一档 |

> ⚠️ 若某项实施后发现与设计文档不符，**应先更新 `OPTIMIZED_DESIGN.md`**，再据此调整本文档，避免两处论述分叉。

## 2. 背景

系统在课程报告 §3.3 的评测中平均得分 **60.2**，对照组 ChatGPT 为 **95.4**。

评测暴露三类失效（报告 §3.3.3）：

1. **多条件查询处理弱** —— 双子句查询只匹配其中一句
2. **事实性不足** —— 推荐了 Steam 上不存在的 *Wolvesville* 与无法验证的 *Sonder*
3. **否定约束执行不稳** —— "不要可爱的"推出 *Super Animal Royale*，"和朋友玩"推出单人游戏

课程评审反馈另指出两点结构性问题：

> "used the LLM mostly to explain already-selected games without improving retrieval or ranking"
>
> "`rank_candidates()` only truncated the top-N retrieval results. That is not really RE-ranking."

即：大模型被用在**不改变推荐结果**的环节，而排序环节实质为空。

---

## 3. 目标与非目标

### 3.1 目标

- **G1** 让大模型作用于**改变推荐结果**的环节（查询理解、排序），而非仅生成文案
- **G2** 建立真正的重排层，而非对召回结果截断
- **G3** 消除事实性幻觉，使其成为**机制上不可能**而非概率降低
- **G4** 建立量化评测体系，使优先级从经验判断转为数据决策
- **G5** 量化与商业产品的差距构成，区分**架构可修**与**模型规模决定**的部分

### 3.2 非目标

- **N1 不更换嵌入模型或生成模型** —— 受限于本地 CPU 硬件，且会污染消融归因
- **N2 不追求超过 ChatGPT** —— 差距中约六成源于模型规模、语料信息量与评测偏向，非架构可解（依据 §11.5）
- **N3 不改动前端** —— 本轮优化全部在检索与生成链路
- **N4 不引入外部 API** —— 保持全本地可复现

## 5. 优先级与依赖

排序依据：**投入产出比**，而非设计文档 §12 的原始顺序。偏离原因见 §5.1。

```
C7 索引重建 ──────┐ 长任务，最先启动
                  │
E1 评测框架 ──────┼──→ 消融实验 ──→ 真实数字
                  │
C3 结构化生成 ────┤
C2 Cross-encoder ─┘

E2 匿名化实验 ──── 独立，随时可做
C4 Tool Calling ── 差异化，最后
E3/E4 工程项 ───── 收尾
```

| 顺序 | 项 | 理由 |
|---|---|---|
| 1 | **C7** | 唯一的长任务（约 10 h），必须最先启动以便并行 |
| 2 | **E1** | 没有它，其余所有工作无法被证明有效 |
| 3 | **C3** | 约 2 h，预估收益最高（第 4 轮 +37），且为**确定性修复** |
| 4 | **C2** | 半天至一天，收益次高，但依赖 ONNX/PyTorch 环境验证，风险中等 |
| 5 | **E2** | 约 2 h，成本低，能把"评测对我们不利"变成有实验支撑的发现 |
| 6 | **C4** | 差异化最大（评审称无人尝试），但小模型 tool calling 稳定性不确定 |
| 7 | **E3/E4** | 不影响评测结论 |

### 5.1 与设计文档 §12 的偏差

`OPTIMIZED_DESIGN.md` §12 将重排列为第 1 步（因评审批评最重），索引重建列为第 3 步。本台账调整为：

- **C7 提前** —— 该文档撰写时数据库不可读、磁盘不足，重建风险高。阻塞已解除（数据已迁出 iCloud，可用空间 79 GB），且它是唯一的长任务，应最先启动
- **C3 置于 C2 之前** —— C3 约 2 h、预估 +37 分且机制上确定；C2 需半天以上、预估 +25 分且有依赖风险。按投入产出应先做 C3

## 6. 全局验收标准

各子 PRD 有各自的验收标准。整个优化程序的完成标志为：

- [ ] **P1** 消融实验表填入真实测量值，覆盖：单路召回 / RRF 融合 / +重排 / 完整系统
- [ ] **P2** 实体幻觉率降至 0，并报告校验机制拦截次数
- [ ] **P3** 报告 §3.5（预期收益）中的预估值被实测值替换或修正
- [ ] **P4** 优化后评测章节（[`section_post_optimization_eval.tex`](../report_sections/section_post_optimization_eval.tex)）的 85 处占位符全部填入
- [ ] **P5** 基线在多次评分协议下重新评分，与新数字可比
- [ ] **P6** 单元测试全绿，解压后单条命令可运行

## 7. 全局风险

| 风险 | 应对 |
|---|---|
| 评测真值存在循环论证（标签既用于检索又用于标注） | 补充已知项检索作为独立验证；报告中明确声明该局限 |
| LLM judge 单次评分含噪声，改进幅度可能被噪声淹没 | 每次比较评分 3 次，报告均值与标准差 |
| 基线旧分数为单次评分，与多次均值不可比 | 基线必须在同协议下重新评分（P5） |
| 小模型 tool calling 不稳定导致 C4 无法交付 | 保留规则解析作为降级路径；即便仅作为实验章节也具价值 |
| 索引体积 94 MB 接近 GitHub 上限 | C7 验收后单独决策提交方式 |
