## 1. 背景与问题

### 1.1 端到端评分退步

[PRD-005](PRD-005-judge-protocol-rerun.md) 的三次盲评结果：修订系统 **60.7**，原系统 **68.7**，
差距超出评委噪声（单轮标准差中位 2.9 分）。

根因定位为推荐条目过于冷门：

| | 推荐条目好评数中位 |
|---|---|
| 原系统 | 8,935 |
| **修订系统** | **468** |
| ChatGPT | 37,721 |

得分最低的 R2（45.3，原系统 73.0）中位仅 **60** 条好评。

### 1.2 机制链条

1. [PRD-001](PRD-001-index-corpus-rebuild.md) 将索引阈值由 `positive > 100` 降至 `> 10`，纳入 12,244 个长尾条目
2. `QUALITY_WEIGHT = 0.25`，`RELEVANCE_WEIGHT = 0.75`
3. 一个仅 60 条好评但语义高度匹配的条目，0.25 的质量惩罚**不足以抵消** 0.75 的相关性优势

### 1.3 原取值的论证有一处未经验证的假设

`OPTIMIZED_DESIGN.md` §8.2 对 0.25 的论证是：

> 因为推荐错类型的神作，比推荐对类型的普通游戏更糟。用户要种田游戏，
> 你给他一个 98% 好评的射击游戏是完全无用的。

该论证**隐含假设"提高质量权重会把不相关条目推上来"**。

实际上 Wilson 质量分只在**已通过 RRF 融合进入前 50 的候选之间**排序，这些候选本就相关。
提高权重不引入不相关结果，只是在相关结果中优先选择口碑更好的。

**这是与嵌入前缀同类的失误**：机制上讲得通的推理，未经测量即被当作定论。

## 2. 扫描实验结果

`eval/sweep_quality_weight.py`，50 条主题查询。检索结果在各行间完全相同，仅重排。

| 权重 | nDCG@10 | P@5 | top-5 好评数中位 |
|---|---|---|---|
| 0.00 | 0.389 | 0.420 | 119 |
| **0.25（当前）** | 0.429 | 0.480 | 267 |
| 0.40 | 0.449 | 0.492 | 630 |
| 0.50 | 0.459 | 0.508 | 911 |
| **0.60** | **0.460** | 0.536 | **1,950** |
| 0.75 | 0.458 | **0.560** | 4,620 |

### 2.1 不存在预期中的权衡

预期是"提高质量权重将牺牲相关性"。**实测两个方向同时改善**：

- nDCG@10 由 0.429 升至 0.460，在 0.60 见顶
- P@5 由 0.480 单调升至 0.560
- 好评数中位由 267 升至 4,620（17 倍）

**0.25 不是权衡点，而是取值偏低**，相关性与口碑同时受其拖累。

## 3. 目标与非目标

### 3.1 目标

- **G1** 使推荐条目的口碑水平回到与原系统可比的量级
- **G2** 不牺牲检索相关性
- **G3** 以端到端评分验证修正有效，而非仅凭检索指标

### 3.2 非目标

- **N1 不回滚 PRD-001 的覆盖率扩大**。长尾覆盖本身有价值；问题在排序权重
- **N2 不改动 Wilson 质量分的内部构成**（`RATING_WEIGHT`、`POPULARITY_REF`）。本次只改一个变量
- **N3 不改动检索、融合、生成**
- **N4 不为提高评分而针对评委偏好调优**。目标是推荐质量，评分是其代理指标

## 4. 需求

| 编号 | 需求 | 理由 |
|---|---|---|
| **R1** | `QUALITY_WEIGHT` 由 0.25 改为 **0.60**，`RELEVANCE_WEIGHT` 相应改为 0.40 | §2 扫描中的 nDCG 峰值点 |
| **R2** | 注释中记录取值依据与扫描结果 | 避免后续再次凭直觉调整 |
| **R3** | 重跑 Track A 与 Track B，确认检索指标未退 | 扫描仅覆盖 Track B |
| **R4** | 重跑 judge 协议（5 轮 × 3 次采集 + 3 次评分） | 见 G3 |
| **R5** | 更新 `OPTIMIZED_DESIGN.md` §8.2 的论证 | 原论证含未经验证的假设 |

## 5. 设计决策

### 5.1 为何取 0.60 而非 0.75

0.75 的 P@5（0.560）与好评中位（4,620）都更高，但 **nDCG@10 已开始回落**（0.460 → 0.458），
表明继续提高将开始牺牲排序质量。0.60 是 nDCG 的峰值点，且好评中位已达 1,950，
与原系统的 8,935 处于可比量级。

**被否决的方案**：取 0.75 以最大化口碑。
**否决理由**：nDCG 已过峰值，且 §3.2 的 N4 明确不以迎合评委为目标——
口碑更高不等于推荐更好，越过 nDCG 峰值即是在用排序质量换取表面分数。

### 5.2 为何不同时收紧索引阈值

**被否决的方案**：将 `MIN_POSITIVE` 由 10 调回 100，从源头排除长尾。

**否决理由**：

1. 覆盖率扩大是 PRD-001 中**唯一被证实有效**的部分（Track A 的 Recall@50 +0.048）
2. 排除发生在召回阶段是不可逆的；排序阶段的压制是可调的。
   这与 [PRD-001 §4.1](PRD-001-index-corpus-rebuild.md) 采用的"召回放宽、排序把关"原则一致
3. 需重建索引（约 8 小时），而本方案只需改一个常量

### 5.3 为何必须重跑 judge 而非仅看检索指标

PRD-005 的教训正是：**C1 与 C5 在检索层取得 2.9–3.5σ 的显著改善，端到端却退步 8 分**。
检索真值衡量"标签是否匹配""是否找回特定游戏"，**均不衡量一个游戏是否值得推荐**。

因此本次修正若仅以扫描中的 nDCG 上升作为验收依据，将重复同一错误。

## 6. 验收标准

- [ ] **A1** `QUALITY_WEIGHT = 0.60`、`RELEVANCE_WEIGHT = 0.40`，注释记录扫描依据
- [ ] **A2** Track A 的 Recall@50 与调整前持平（重排不改变候选集合，应完全相同）
- [ ] **A3** Track B 的 nDCG@10 ≥ 0.45
- [ ] **A4** 5 轮 judge 采集中，推荐条目好评数中位 ≥ 1,500
- [ ] **A5** judge 三次评分完成，修订系统均值**高于** PRD-005 记录的 60.7
- [ ] **A6** 与原系统 68.7 的差距，或转为正向，或缩小至评委噪声（2.9 分）以内
- [ ] **A7** 单元测试全部通过
- [ ] **A8** `OPTIMIZED_DESIGN.md` §8.2 已据实测更新

> **A5/A6 可能不达成。** 若端到端分数未回升，则说明退步另有原因，
> 需在 PRD-005 §10.3 的根因分析上继续排查，而非反复调整本权重。

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 端到端分数未回升 | 根因判断有误 | A5/A6 如实记录；不得为凑分反复试参数 |
| 长尾发现能力下降 | 削弱相对通用大模型的差异化 | 记录好评数中位；1,950 仍远低于 ChatGPT 的 37,721 |
| 50 条查询上的最优值不具普适性 | 过拟合扫描集 | 以 Track A（500 条）交叉验证 |
| 评委知名度偏误使分数虚高 | 误判为真实改善 | 与好评数中位并列报告，说明分数来源 |
